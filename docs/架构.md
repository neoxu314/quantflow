## 入口与核心流程

```text
CLI / Web
├─ Stock Scan ────────────── execution.scanner ─ 日线检查 → 指标结果
├─ Watchlist Run ─────────── execution.Executor ─ 行情 → 指标 → 策略 → 覆盖率和报告
└─ Task Run ─ orchestration.Orchestrator ─────── 多个 ExecutionJob → 合并结果和报告
```

| 模块 | 职责 |
| --- | --- |
| `cli.py`、`web/` | 命令入口、FastAPI 服务、TypeScript 页面、运行预检、队列及历史 |
| `config/` | YAML 配置、独立的回看窗口配置和运行日志 |
| `orchestration/` | 加载任务 YAML、解析股票池、注册策略、顺序执行及汇总任务 |
| `execution/` | 解析股票池、确定数据窗口、执行日线分析、逐股记录结果和 checkpoint |
| `data/` | 统一股票代码、交易所日历、主备源路由、日线质量检查和基本面事实 |
| `indicators/` | 从 YAML 合并参数，按所需字段顺序计算指标，缺失样本保留质量状态 |
| `strategies/` | 买卖信号条件和组合策略。任务使用注册表中的策略 ID |
| `reports/`、`artifacts.py` | Markdown、结果覆盖、原始行情快照、严格 JSON、原子写入和产物归属 |
| `backtest/rebound.py` | 从冻结 CSV 复算三种反弹信号，评估 5/10 交易日退出 |
| `backup.py` | 备份 Runs SQLite、预设、检查点及已登记产物并验证 |
| `risk/`、`execution/alerts/` | 风险模块预留及告警接口 |

## 结果与状态

策略执行先按市场确定最近完整交易日，按相同请求窗口和供应商能力分组。批量任务每批最多
下载 50 只，计算并保存后继续下一批。主备源回退和有限补查按受影响的股票执行。
同一股票的指标由所有策略共享输入，每条策略独立计算并归并命中。

Web 进程在 SQLite 对应的排他锁下运行。服务按队列分配一个 active slot。
下载和分析阶段的进度通过 SSE 和 Runs API 提供，日志从实际文件读取。
运行结束时把终态写入独占的产物清单，再记录到 SQLite。数据库提交中断后可以从核验过的清单恢复。

`output_path` 的用户配置是基础目录。每次 CLI 或 Web 运行在
`<base>/[日期/]runs/<run_id>/` 下保存文件。Resume 创建新运行，只复用已经核验的成功分析，
保持原数据截止时点。更多故障与重放细节见 [运行契约](reliability-and-data-contracts.md)。
