## 接下来最值得做的四项

1. **对真实行情做验收。** 在有权限的市场各取普通日、半日市或假日、复权事件和数据迟到样本，对比完成交易日、可用来源和最终信号。用真实超时和限流测量取消延迟，验证断开后队列只继续一次。将 A 股新年度日历纳入年末检查。
2. **校准超卖和反弹的定义。** 当前 `daily_bull_oversold` 寻找多头结构里 J 低于阈值且仍守住多空线的股票，`daily_bull_mid_range` 寻找多头通道内回调。两条规则可能同时命中。用历史样本分别比较首次触发、持续超卖、回升确认及退出规则，计入成交约束、成本和滑点。分别看短期收益分布、回撤和触发后的可执行性，再决定是否改默认规则。
3. **先用现有文件验证二次审核。** 选几次不同市场、行情覆盖程度不同的运行。以 `Run_Summary.json` 看完整性，使用 `<task>.json` 或 `Combined_Results.json` 获取结构化候选，再用 Markdown 阅读上下文。合并时按市场、代码及信号交易日去重，保留所有命中策略和覆盖状态。记录筛选证据的独立截止时刻。历史试点只使用该时刻前已披露的信息。
4. **根据试点结果决定是否开发。** 先用存好的审核指令或 Skill，不改项目即可试验。需要频繁手工整理文件时，优先增加一次导出和版本化字段。需要无人值守执行、批量回写与复跑时，再把相同的数据接口接到独立任务或 QuantFlow 的报告后处理。

## 报告加 ChatGPT Skill 与内置模型的比较

| 维度 | 报告加 ChatGPT Skill | QuantFlow 内置模型 API |
|---|---|---|
| 使用方式 | 运行后选择并上传报告和结果文件，人工检查证据及筛选结果。适合少量候选和快速调整审核规则。 | 每次运行后按设置自动提交筛选，适合固定频率和较大候选量。接口失败时量化报告可独立交付。 |
| 外部取证 | 如当前会话具备浏览能力，可临时核对公告及财报并附链接。市场覆盖、网页可达性和批量校验需要人工检查。 | 需要单独维护公告、财报及估值来源和字段映射。接入模型本身只提供分析能力，证据覆盖仍依赖数据源。 |
| 可追溯性 | 保存输入文件、审核指令版本、输出和链接。模型、工具和网页随时间变化，复跑会有差异。 | 可自动保存研究时间、输入快照及哈希、模型与规则版本、结构化结果、引用和异常。 |
| 成本和维护 | 上线快，无需为项目配置 API。运行频率提高后，上传、复核和归档会占用时间。 | 要维护 API 密钥、用量及延迟、重试、限流、结构校验、外部文本处理和故障降级。 |
| 数据边界 | 审核所需的候选和事实进入 ChatGPT 工作区。个人自选池、路径、凭证及数据供应商限制需要在上传前考虑。 | 可在代码里筛选最少字段并选择供应商，仍须评估传输范围和对方的数据处理方式。 |

ChatGPT Skill 的可用性取决于套餐、工作区设置和产品界面。若当前界面没有 Skill 入口，可以先用固定审核指令和相同输入文件。[OpenAI 的 ChatGPT Skills 说明](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)

## 二次审核需要哪些证据

默认按信号后 1–2 周评估。区分已存在的重大基本面瑕疵、窗口内可能改变交易判断的催化，以及通常要更长时间才能传导至业绩的风险。产品竞争若已触发指引变化或窗口内有关键事件，可提高复核优先级。对没有明确短期传导证据的竞争压力，记录观察条件和时间。

- **技术信号。** 保存原始 run ID、规则、市场、信号完成交易日、价格复权口径和运行覆盖。空表、过期及停牌等先按覆盖状态处理。
- **基本面。** 记录财报期末、公开披露日、原币与单位。按行业审查盈利、经营现金流、负债与流动性，注明一次性项目及近年变化。指标口径一致后再计算筛选规则。
- **估值。** 优先比较同一口径的行业同业与个股历史区间。对亏损公司或周期行业单独解释指标适用性，保留亏损、分母缺失和未覆盖的差别。
- **事件。** 记录事件发生日和公告日，注明审核截止时刻、证据链接、适用主体及重大程度。监管处分、审计意见变更、财务重述、重大诉讼和债务事件按原始披露优先核对。查不到足够证据时标为“资料不足”。
- **审核输出。** 每个候选给出“保留观察、暂缓复核、排除、资料不足”之一，列出理由、引用和下一步人工核对项。预先定义的硬性排除条件可由规则执行，模型负责归纳证据、解释冲突和标记不确定性。可以给不同策略使用不同审核标准。

试点先标注一批含重大风险、正常回调和资料不足的历史候选，与“人工或固定规则审核”对照。记录有证据的判断比例、漏掉的明确风险、误排除数量、单次审核时间和结果复核率。若规则即可覆盖主要判断，继续用规则和人工取证也成立。若 Skill 能减少复核时间，但手动步骤成为明显负担，再实现自动化。可先做独立报告后处理，待流程稳定后再接到 Web 界面。
