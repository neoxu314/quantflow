
# 个人多市场股票量化监控系统需求规格说明书 V1.0

## 1. 引言
### 1.1 项目背景
开发者维护多个观察仓，涵盖 A 股、港股、美股、日股、韩股等市场。日常需监控上百只股票，手动翻阅 K 线耗时且易遗漏信号。本项目旨在构建一个自动化的**量化监控系统**，每日拉取数据、计算指标、运行策略，生成买卖建议报告，**所有交易决策由开发者最终人工判断**。

### 1.2 核心原则
- **只监控，不交易**：系统输出建议，不执行任何下单。
- **个人可维护**：单人在 Ubuntu 环境下借助 AI 编程工具 (opencode) 即可开发与维护。
- **低成本优先**：优先使用免费数据源，开发复杂度最小化。
- **快速可用**：阶段一立即解决“观察仓监控”核心痛点，不追求全市场扫描。

## 2. 系统分层架构
系统划分为四层，层间单向依赖：

```
┌───────────────────────────────────────────────────┐
│                  监控层 (Monitor)                   │
│  观察仓管理、持仓管理、信号聚合、报告生成、通知      │
└───────────────────────────────────────────────────┘
                        ↑
┌───────────────────────────────────────────────────┐
│                  策略层 (Strategy)                  │
│  买入策略、卖出策略、减仓策略(预留)                 │
└───────────────────────────────────────────────────┘
                        ↑
┌───────────────────────────────────────────────────┐
│                  指标层 (Indicator)                 │
│  KDJ, MACD, RSI, 自定义指标                        │
└───────────────────────────────────────────────────┘
                        ↑
┌───────────────────────────────────────────────────┐
│                  数据层 (Data)                      │
│  A股(baostock), 其他(yfinance), 板块(akshare)       │
└───────────────────────────────────────────────────┘
```

## 3. 数据层详细需求
### 3.1 数据源
- **A 股**：Baostock (主力)，获取日线/周线/月线，前复权 (`qfq`)。
  - 备用降级：Tushare (积分限制，仅未复权，仅在主源失效时临时使用，需标记)。
- **港股、美股、日股、韩股**：yfinance，自动获取调整后收盘价 (Adj Close)。
- **行业板块/成分股**：akshare (暂不用，预留)。

### 3.2 拉取机制
- **全实时拉取**：每次运行时，从数据源直接获取最近 N 日数据（N 可配置，默认 250 个交易日，供指标计算）。
- **极轻量快照备份**：拉取后，立即将原始数据 DataFrame 保存为带日期的 CSV/Parquet 文件。格式：`data/snapshots/{market}/{symbol}_{YYYYMMDD}.parquet`。该文件仅用于事后审计，不参与计算流程。
- **交易日判断**：
  - 使用 `pandas_market_calendars` 识别各海外市场交易日。
  - A 股交易日通过 akshare 或本地日历文件判断。
  - 脚本运行时，仅当昨日是该市场交易日时拉取最新数据，否则空运行并生成提示。
- **容错**：单个股票/市场拉取失败，记录错误日志 (logging)，继续处理下一个。不阻断整体流程。

### 3.3 前复权偏差（已知局限）
港股等非美市场，yfinance 的 Adj Close 可能不含分红调整，导致技术指标轻微偏移。现阶段接受此偏差，未来可扩展复权因子模块。

## 4. 指标层详细需求
### 4.1 技术指标实现方式
- 每个指标为一个标准 Python 函数，接受 pandas DataFrame (包含 `open, high, low, close, volume`) 和参数字典，返回添加了新列的 DataFrame。
- 多个指标可采用链式调用或列表顺序执行：系统维护一个 `indicators_config` 顺序列表，如 `[calc_ma, calc_kdj, calc_macd, my_indicator]`，依次执行，**指标间依赖顺序由开发者手动管理**。
- 自定义指标同样按此规范编写，放入 `indicators/custom.py`。

### 4.2 内置指标清单（阶段一）
- MA (简单/指数移动均线)
- KDJ
- MACD
- RSI
- 自定义独有指标（基于价格均线的公式）

### 4.3 多周期处理
策略可能同时用到日线、周线、月线指标。数据拉取阶段已获取各周期 K 线，指标层分别计算，然后在策略层按股票代码对齐。

## 5. 策略层详细需求
### 5.1 策略形态
全部为触发式规则，策略的输出为 **信号：买入 / 清仓卖出 / 减仓 (预留)**。

**示例**：超卖策略 — 当日 KDJ 的 J<20 且价格处于多头区间（如 50 日均线向上），触发买入建议。

### 5.2 策略实现与参数管理
采用**参数化代码策略**：
- 每个策略实现为一个 Python 类/函数，包含逻辑代码。
- 可变参数（如阈值、周期）存储在 `strategies/config.yaml` 中，策略运行时读入。
- 修改参数直接编辑 YAML 文件，无需改代码。
- 新增策略由 AI 辅助编写新函数，并在配置文件注册。

### 5.3 策略运行范围
- **买入策略**：仅对**观察仓内的股票**运行。不同观察仓分别跑策略，报告按时分组显示。
- **卖出/减仓策略**：仅对**当前持仓**（positions.yaml 中股数 > 0）运行，不依赖观察仓。

### 5.4 多策略共存
多个买入策略（如超卖反弹、趋势跟随等）各自独立运行，信号按策略聚合展示，不存在互斥或投票。

## 6. 监控层详细需求
### 6.1 观察仓管理
- 观察仓以文件形式存放：`watchlists/{仓名称}.json`，格式示例：
  ```json
  {
    "name": "价值投资仓",
    "stocks": [
      {"symbol": "000001.SZ", "name": "平安银行", "market": "A"},
      {"symbol": "00700.HK", "name": "腾讯控股", "market": "HK"}
    ]
  }
  ```
- 管理操作：支持命令行脚本 (如 `python manage.py add-stock ...`) 增加/删除/迁移股票，自动更新 JSON 文件。
- 同时也接受手动编辑 JSON 文件（开发者可选）。

### 6.2 持仓管理 (手动对账本)
- 持仓文件：`data/positions.yaml`，记录每只股票的**系统内应有持仓**。
- 交易录入：开发者真实成交后，运行命令：
  ```
  python record.py --symbol 000001.SZ --action buy --quantity 1000 --price 12.50 --date 2026-04-22
  ```
  若未提供 `--price`，则以运行当日收盘价作为成本；`--date` 默认为上次计算日。
- 系统自动计算**平均成本**：同一股票多次买入时，按加权平均更新成本；卖出时按先进先出或平均成本减少（默认平均成本），自动更新持仓数量。
- 系统基于 `positions.yaml` 计算浮动盈亏，需在报告中展示。

### 6.3 信号聚合与报告格式
每日运行结束后，生成 Markdown 报告 (`reports/report_YYYYMMDD.md`) 及邮件正文。
报告结构要求：

```
# 股票监控日报 YYYY-MM-DD

## 一、数据状态
- A股数据更新成功：xxxx 只
- 港股数据异常：...

## 二、持仓概览
| 代码 | 名称 | 持仓量 | 成本 | 现价 | 盈亏% |
|------|------|--------|------|------|-------|
| ... | ... | ... | ... | ... | ...% |

## 三、卖出策略信号
### 策略：趋势破位清仓
- **建议清仓**：000001.SZ (平安银行), 01810.HK (小米集团)
### 策略：...(减仓留白)

## 四、买入策略信号
### 策略：超卖反弹
- 观察仓【价值投资仓】：000001.SZ, 600036.SH
- 观察仓【短期热点仓】：无触发
- 观察仓【港股高股息仓】：01810.HK
### 策略：均线多头排列
- ...
```

### 6.4 通知方式
- **阶段一必须实现**：
  - Markdown 报告文件本地生成
  - 邮件发送（SMTP 配置，Gmail/QQ 邮箱）
- **阶段二扩展**：
  - Web 仪表盘（Flask/FastAPI 单页应用，本地访问）
  - 即时通讯推送（微信/钉钉/Telegram bot，通过 webhook 发送摘要）

## 7. 辅助工具需求
### 7.1 观察仓/持仓管理 CLI
提供统一管理入口，示例命令：
- `python manager.py watchlist add --name "价值投资仓" --symbols 000001.SZ,00700.HK`
- `python manager.py trade --symbol 000001.SZ --buy 500 --price 12.3`
- `python daily.py` （执行完整监控流程）

### 7.2 日志与审计
- 所有拉取失败、计算异常写入 `logs/monitor.log`，保留最近 90 天。
- 数据快照保留策略：每市场每日一份，保留 30 天。

## 8. 非功能需求
- **运行环境**：Ubuntu 桌面/服务器，Python 3.10+。
- **依赖管理**：使用 `requirements.txt` 或 `pyproject.toml`。
- **性能**：测试集 200 只股票多市场，每日全流程完成时间 ≤ 10 分钟。
- **可维护性**：代码分层清晰，每个模块可独立测试，充分注释以便 AI 辅助维护。
- **安全**：涉及邮件密码、API Key 等敏感信息使用 `.env` 文件，不提交版本控制。

## 9. 开发路线图
- **第一阶段 (MVP)** – `v0.1.0`
  - 数据层：实现 baostock (A股前复权) + yfinance (其他) 拉取，快照存储。
  - 指标层：MACD, KDJ, RSI, MA 及 1 个自定义指标示例。
  - 策略层：2 个买入策略、1 个清仓卖出策略（参数化配置）。
  - 监控层：观察仓文件管理、手动交易录入、Markdown 报告 + 邮件发送。
- **第二阶段** – `v0.2.0`
  - 增加减仓策略预留位（初步实现简单减仓逻辑）。
  - Web 仪表盘基础版。
  - 即时通讯推送。
- **第三阶段** – 未来
  - 候选池自动筛选（流动性、市值等）。
  - 更完整的多数据源容错切换。

## 10. 已知局限与风险
- 港股、日韩股等复权精度有限。
- 纯实时拉取，若连续多日脚本未运行，中间缺失数据不会补全，需运行脚本前留意（可通过快照覆写机制缓解近 5 日问题）。
- 账户持仓依赖人工及时录入，遗忘会导致策略信号失真。
- 免费数据源（尤其 yfinance）有速率限制，全市场扫描基本不可行，必须基于观察仓。
