# 为什么 QuantFlow 是无可替代的

> 生成日期: 2026-05-03
> 背景: 与 VeighNa 等成熟开源项目对比后的战略定位文档

---

## 一、我的核心需求

我是一个股票量化初学者，我的日常工作流程是：

1. **挑选一个信任的股票池** — 覆盖 A股、美股、港股、韩股、日股等多个市场（约 70 只）
2. **配置监控策略** — 定义哪些技术指标组合触发买入或卖出信号
3. **每日自动扫描** — Linux cron 定时任务在盘后自动运行，扫描全量 watchlist
4. **接收报告，人工判断** — 生成 Markdown 报告，我逐条审查信号，最终由我自己决定是否交易

**核心诉求: 机器替我节省时间（扫描成百上千只股票），但我自己做最终决策。**

## 二、现有开源项目对比

### 开源项目生态全景

| 项目 | 核心定位 | 能帮我做什么 | 不能帮我做什么 |
|---|---|---|---|
| **VeighNa (vnpy)** | 实盘交易框架 | 自动下单、CTA回测、多市场交易接口 | 批量盘后扫描、watchlist管理、Markdown报告、人工审信号 |
| **Backtrader** | 策略回测引擎 | 验证策略历史表现、优化参数 | 每日自动化扫描、多股票池管理、可视化报告 |
| **Qlib (微软)** | 因子研究平台 | 机器学习选股、大规模因子计算 | 实时监控、人工决策闭环、多市场一站式 |
| **Zipline (Quantopian)** | 事件驱动回测 | 策略仿真、组合分析 | 盘后扫描、报告生成、cron自动化 |
| **TradingView** | 图表看盘工具 | 可视化技术分析、社区策略 | 自动化扫描、自有股票池批量监控、本地数据 |
| **RiceQuant/JoinQuant** | 在线量化平台 | 回测、模拟交易、社区策略 | 本地部署、自定义工作流、私有数据 |

### 为什么它们都不行？

**VeighNa（最常被拿来参考的项目）的基因矛盾：**

VeighNa 的核心设计假设是「**你要自动交易**」。它的整个架构——事件驱动引擎、30+ 交易接口网关、tick级实时行情、委托报单回报——都是围绕实盘下单构建的。

而我需要的是「**你帮我扫，我自己看**」。这在 VeighNa 里是一个不存在的用例。

| 我想要 | VeighNa 的做法 | 矛盾点 |
|---|---|---|
| 管理一个 watchlist（70只股票） | 没有 watchlist 概念，管理的是交易合约 | 需要逆向改造 |
| 盘后批量扫全量股票 | 事件驱动，每根tick触发策略 | 架构不匹配 |
| 生成 Markdown 报告供我阅读 | 无报告系统，输出是交易日志 | 完全没有 |
| cron + CLI 一行命令 | 需要启动 VeighNa Station + Trader 桌面GUI | 不适合 headless 服务器 |
| 信号共振（多个策略同时触发） | 单品种单策略 | 需要自行拼凑 |
| 零代码配置策略 | Python 类继承 CtaTemplate | 学习成本高 |

**其他项目的核心问题：**

- **Backtrader/Zipline**: 只有回测，没有监控扫描
- **Qlib**: 面向机构量化研究，不是个人日常工具
- **TradingView**: 在线工具，无法自动化、无法本地部署、无法 cron
- **RiceQuant/JoinQuant**: SAAS 平台，数据/策略不掌握在自己手里

## 三、QuantFlow 的独特价值

### 3.1 填补了市场空白

**QuantFlow 是目前极少见的「扫描 → 信号 → 报告 → 人审」完整链路的开源实现。**

这条链路之所以罕见，是因为：

- **做大厂/机构的** → 做的是自动交易系统（信号不给人看，直接下单）
- **做学术研究的** → 做的是回测验证（关注策略收益，不关注日常监控）
- **做个人工具的** → 做的是看图软件（手动一只一只翻，不批量扫）

**没有人专门为"盘后扫描 + 人工决策"这个场景做产品。QuantFlow 填补了这个空白。**

### 3.3 不可替代性清单

| 特性 | QuantFlow | 你能在别处找到吗？ |
|---|---|---|
| 多市场一站式（A+美+港+韩+日） | ✅ YAML配置，自动选数据源 | 🔴 VeighNA需分别对接不同Gateway |
| Watchlist 概念 | ✅ YAML文件，Web UI管理 | 🔴 无直接对应概念 |
| YAML驱动策略配置 | ✅ 零代码即可调整 | 🔴 都需要写Python代码 |
| 策略共振信号 | ✅ 多策略组合，按共振度排序 | 🟡 需要自己拼凑 |
| Markdown 报告 | ✅ 自动生成，按策略分组 | 🔴 无此功能 |
| cron 友好 | ✅ CLI 一行命令，headless | 🟡 VeighNa需要桌面GUI |
| 人工决策闭环 | 设计时就假设人来判断 | 🔴 所有框架都默认自动交易 |
| 代码 100% 可控 | ✅ 每一行都是自己的 | 🟡 使用别人的框架要理解其架构 |

## 四、未来方向建议

QuantFlow 的核心价值是让"人审"环节更高效。以下建议全部围绕这一目标展开，按优先级排列：

### 4.1 ✅ 信号质量提升 — K线图嵌入报告

**问题：** 当前报告只有文字信号，判断准确性时仍需额外打开交易软件看K线。

**方案：**

- 每个信号附带一张 K线图截图（日K，含标注的关键指标线：均线、KDJ、双线等）
- 技术选型：`matplotlib`（轻量，适合服务端生成PNG）或 `pyecharts`（交互式，适合Web查看）
- Markdown 报告以 `![图](path/to/signal.png)` 嵌入，打开报告即可看图判断

```
示例报告片段：

### 🔵 Buy - daily_bull_oversold (3 stocks)

| Code | Name | Signal |
|------|------|--------|
| 002594.SZ | 比亚迪 | ✅ |
![002594.SZ K线图](daily_reports/2026-05-03/002594.SZ.png)
```

**预期收益：** 省去"看报告 → 切软件 → 翻K线"的额外步骤，报告即全景。

**工作量：** 中等。需要新增图表生成模块 + 报告层集成。

---

### 4.2 ✅ 信号历史回溯 — 轻量级回测引擎

**问题：** 信号出来了，但不知道这个信号在过去出现的频率和胜率。

**方案：**

- 不引入 VeighNa 那么重的回测框架，而是做一个简单的信号回溯器
- 逻辑：对每只股票的历史数据，用当前策略规则回跑一遍，统计：
  - 该信号过去 N 个月/年出现过多少次
  - 每次信号出现后 N 天的涨跌幅（胜率）
  - 平均持仓收益率

```
示例报告附加信息：

### 🔵 Buy - daily_bull_oversold — 002594.SZ 比亚迪

信号详情: 超卖 J=14.2, 处于多头通道
📊 历史回溯: 过去 2 年该信号出现 18 次
              5日胜率 61% | 10日胜率 56% | 平均收益 +2.3%
```

**预期收益：** 增加信号的可信度参考维度，不再"盲人摸象"。

**工作量：** 中等。需要在 reports 层接入历史数据回跑逻辑，存储回溯结果可用 SQLite。

---

### 4.3 ✅ 噪音过滤 — 市场环境过滤器

**问题：** 大盘暴跌时，技术面的做多信号准确率会大幅下降，但仍然会出现在报告中。

**方案：**

- 新增一个"市场环境判断"层，在策略扫描之前/之后执行：
  - 判断基准：主要指数（沪深300 / 标普500）是否在关键均线下方（如 MA20 / MA60）
  - 如果市场处于"弱势"，可以做以下处理之一：
    1. **压制做多信号** — 不在报告中显示 buy 信号，或标记为 ⚠️ 警告状态
    2. **降级优先级** — 信号仍然显示，但排在"强势市场"信号之后
    3. **标注环境** — 信号旁附加"市场弱势中，需谨慎"提示
- 可配置的过滤器：
  - `market_filter.enabled: true`
  - `market_filter.indices: [000300.SH, ^GSPC]`
  - `market_filter.bear_threshold: "MA60"`
  - `market_filter.action: "suppress" | "warn" | "downgrade"`

```
示例报告头部：

⚠️ 市场环境警告: 沪深300 处于 MA60 下方（弱势）
   本次扫描共发现 12 个做多信号，已标记为 ⚠️ 需谨慎评估

### ⚠️ Buy - daily_bull_oversold (压制状态下)
```

**预期收益：** 大幅减少熊市/弱势中的无效信号（噪音），提升报告的信噪比。

**工作量：** 低。新增一个 market_filter 模块，策略匹配后增加一层过滤即可。

---

### 4.4 ⬜ 信号优先级排序 — 置信度打分

**问题：** 当一天扫出 50 个信号时，不知道该先看哪个。

**方案：**

- 给每个信号计算一个"置信度分数"，因素包括：
  - **共振数量** — 多少个策略同时触发（最重要因子）
  - **历史胜率** — 来自 4.2 的回溯数据
  - **市场环境** — 4.3 过滤器的结果（强势市场的信号权重更高）
  - **指标强度** — 如 KDJ 的 J 值越低（超卖越深），分数越高
  - **成交量因子** — 放量信号的置信度高于缩量
- 公式（简化概念）：
  ```
  score = resonance_weight * 30%
        + historical_winrate * 25%
        + market_environment * 20%
        + indicator_strength * 15%
        + volume_factor * 10%
  ```
- 报告按 score 降序排列，优先展示最高分的 Top 10

```
示例报告：

📊 本次扫描共产生 47 个信号 | Top 10 推荐:

排名 | 代码 | 名称 | 置信度 | 共振 | 历史胜率
-----|------|------|--------|------|----------
 1    | 002594.SZ | 比亚迪 | ⭐⭐⭐⭐ 92 | x2 | 61%
 2    | NVDA.US   | 英伟达 | ⭐⭐⭐   85 | x1 | 58%
...
```

**预期收益：** 解决信息过载问题，让你每天只看最值得关注的信号。

**工作量：** 中到高。需要建立打分模型、调参、验证打分效果。可作为远期目标。

## 五、结论

**QuantFlow 不是 VeighNa 的替代品，它解决的是一个 VeighNa 从来没想过要解决的问题。**

- VeighNa 解决的是"如何自动化交易"
- QuantFlow 解决的是"如何高效发现信号 + 人工判断"

**这两个问题的交集很小。** 就像"自动驾驶"和"智能导航"——前者帮你开车，后者帮你找路。如果你需要的是导航，你不需要去买一辆自动驾驶汽车来自己改装。

### 渐进式发展路径

```
人在决策               + K线图嵌入报告
                       + 市场环境过滤器
```

**现在的路，是对的。继续走。**
